# Week 6. State Drift & 고전 `terraform import`

### [개념] 오늘의 목표 & 핵심 순간 ⭐
두 가지를 겪는다. (1) **Drift**: 콘솔에서 몰래 바꾸면 `plan`이 "코드와 실제가 다르다"고 감지. (2) **고전 import**: 콘솔에서 이미 만든 리소스를 Terraform 관리로 편입 — 그런데 **설정을 손으로 다 적어 넣는 "노가다"**가 필요하다. 이 고통이 Week7 최신 import의 동기다.

### [실습] 1. 코드로 S3 버킷 하나 생성
`week6/main.tf`:
```hcl
terraform {
  required_version = ">= 1.9"
  required_providers { aws = { source = "hashicorp/aws", version = "~> 6.0" } }
}
provider "aws" { region = "ap-northeast-2" }

resource "aws_s3_bucket" "managed" {
  bucket = "boaz26-w6-managed-kdh1834"
  tags = { Name = "managed", Env = "study" }
}
```
```bash
cd week6 && terraform init && terraform apply
```

### [실습] 2. ⭐ Drift 만들기 — 콘솔에서 태그 변경
AWS 콘솔 → S3 → `boaz26-w6-managed-kdh1834` → Tags에서 `Env` 값을 `study` → `HACKED`로 수정 저장.
그리고 터미널에서:
```bash
terraform plan
```

### [확인] Drift 감지
`plan`이 `~ update in-place`로 `Env` 태그를 `"HACKED" -> "study"`로 되돌리려 함.
→ **코드가 진실의 원천(source of truth)**. `terraform apply`하면 코드 상태로 교정된다.

### [관찰 ✍️] 기록
- plan이 감지한 drift 필드: ___
- (선택) `apply` 후 콘솔에서 태그가 다시 `study`로 돌아갔는가: ___

### [개념] 이제 반대 상황 — 콘솔이 먼저 만든 리소스
Terraform이 모르는 리소스는 state에 없다. 코드에 `resource` 블록만 써도 `apply`하면 "이미 존재한다"며 충돌. → **import**로 기존 리소스를 state에 편입해야 한다.

### [실습] 3. 콘솔에서 "관리 안 되는" 버킷 수동 생성
AWS 콘솔 → S3 → **Create bucket** → 이름 `boaz26-w6-imported-kdh1834`(유일하게) → 리전 `ap-northeast-2` → 생성. (Terraform 코드엔 아직 없음)

### [실습] 4. ⭐ 고전 import — 빈 블록 + import 명령
`main.tf`에 **속성 없는 뼈대** 추가:
```hcl
resource "aws_s3_bucket" "imported" {
  bucket = "boaz26-w6-imported-kdh1834"
}
```
```bash
terraform import aws_s3_bucket.imported boaz26-w6-imported-kdh1834
```

### [확인] import 됨
`Import successful!` → 이제 state에 들어옴. 하지만:
```bash
terraform plan
```

### [개념] ⭐ 여기가 "노가다"의 시작
import는 **state만** 채운다. **코드(HCL)는 자동으로 안 채워진다.** 그래서 `plan`이 여전히 차이를 보이거나, 실제 버킷의 세부 설정(versioning, ownership, tags 등)이 코드에 없어서 계속 어긋난다. → **`terraform state show`로 실제 속성을 보고, 손으로 하나씩 HCL에 옮겨 적어** `plan`이 `No changes`가 될 때까지 반복해야 한다.

### [실습] 5. `No changes` 될 때까지 코드 채우기
```bash
terraform state show aws_s3_bucket.imported    # 실제 속성 확인
```
출력을 보고 필요한 설정을 코드에 채운다(예: 태그를 콘솔에서 달았다면 동일하게):
```hcl
resource "aws_s3_bucket" "imported" {
  bucket = "boaz26-w6-imported-kdh1834"
  # state show에서 본 값들을 손으로 옮겨 적기 (노가다 ⭐)
  tags = {
    # 콘솔에서 넣은 태그가 있다면 그대로
  }
}
```
```bash
terraform plan     # 목표: "No changes. Your infrastructure matches the configuration."
```

### [함정] import 관련 흔한 에러
- `Cannot import non-existent remote object`: 버킷 이름/리전 오타.
- `Resource already managed by Terraform`: 이미 import됨(중복 실행).
- S3는 versioning·ownership·ACL이 **별도 리소스**(`aws_s3_bucket_versioning` 등)로 분리 → 각각 import해야 완전. 오늘은 버킷 본체까지만.

### [정리] destroy 체크리스트
```bash
terraform destroy   # managed + imported 둘 다 삭제됨(이제 둘 다 관리 대상)
```
- [ ] 두 버킷 모두 삭제 확인
- [ ] import한 리소스도 이제 Terraform이 지운다는 점 확인
